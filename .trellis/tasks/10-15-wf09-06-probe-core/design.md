# Design
Add public connection_probe module with ProbeEngine, ProbeKind, ProbeCancellation and structured ProbeResult. Existing network_tools executes on remote SSH and is unchanged; this core probes the local machine's direct route only, never a proxy/jump route.
Fixed total deadline 5 seconds across DNS + TCP; up to 4 active operations and 4 blocking system resolver calls. Acquire permits with try_acquire_owned, returning unavailable/busy immediately. Resolver permit moves into blocking closure, so timeout/cancel drops waiting but never releases capacity while OS lookup still runs. IPv4/IPv6 literals bypass resolver. Hostnames use bounded ASCII labels (punycode supported as ASCII, raw Unicode rejected); URL/userinfo/ports/whitespace/options rejected explicitly.
Keep at most 16 resolved addresses. DNS returns a bounded count and truncation flag, not addresses. TCP tries sequentially with 1 second per address inside total deadline; connect-only, no payload, drops successful socket immediately. If no success and any address timed out or was omitted, report indeterminate timeout/address_limit instead of falsely claiming definitive failure. Outcomes: success/cancelled/timed_out/unavailable/failed/invalid_input; reasons carry fixed codes only. Result is Serialize, no input target or raw OS error. Cancellation is one-way watch state and supports cancel-before-start. All resources are RAII-owned; dropping the caller future drops sockets and operation permits, resolver guard remains in worker.
No IPC registration/UI/persistence changes in this cut. Engine must be a single app-managed owner when later wired; don't instantiate per request or scope caps can be bypassed. Existing tokio features/dependencies suffice.
