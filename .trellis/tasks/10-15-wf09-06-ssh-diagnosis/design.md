# Design
Lightweight pure connectionFailureDiagnosis module reuses connectionErrorCodes and jumpRuntime parser. Result is fixed phase/reason/index plus optional node connection reference, never message/raw/host/username/credentials. Known node stage direct_tcpip maps forwarding, auth maps auth, connect maps combined connection/handshake. Stable code families cover host keys, proxy, auth/key/Vault config, terminal channel and jump config; unknown has no certainty. Reason is stable network kind or timeout/rejected/failed.
ConnectionStepErrorDetail owns transient diagnosis and resolved display label. Existing failure UI gains extracted ConnectionFailureDetails; prioritize sanitized summary over legacy raw text. Diagnostic ID is validated before display, not used as the failure headline. Existing retry clears entire errorDetail, Host Key and credential flows unchanged. Progress uses classified step index while preserving old fallback. No new IPC/backend work.
Use existing component/token/i18n conventions; ui-ux-pro-max unavailable as previously established. User explicitly authorized all remaining WF09 development without repeated confirmation (2026-10-15); reviews/manual acceptance remain deferred.
