# Design
Add appearance.terminalKeywordRules to existing settings, default empty. Lightweight shared contract validates bounded typed literal rules; invalid stored lists fall back atomically to empty for compatibility, without salvaging or truncating user text. UI uses three labelled textareas with existing settings input/action styles, SettingsRow, and Lucide. Explicit Save applies entire validated draft; Discard resets to current saved value. Instructions disclose local plain-text settings and discourage secrets. Leading/trailing whitespace is rejected explicitly, internal spaces and punctuation are literal. No regex UI, no separate store, no autosave per keystroke.
TerminalPanel receives rules at both SSH and Local render sites; highlighter compiles escaped literal regexes only on creation/rule change, custom priority65 vs builtin60 and version70. Preserve punctuation/spacing of literals (no token trimming), Unicode boundaries, existing cap and palette. setRules clears/redraws decorations without reconstructing terminal or session.
ui-ux-pro-max is unavailable in this environment (prior verified discovery); reuse existing shared settings controls/token styles under user's authorized direct development. GUI acceptance deferred, automated tests not a substitute.
