# Design
Rust app-managed registry maps exact runtime session IDs to capture entries. Start is checked against SSH/Local sessions under the session lock. Worker creates the file and owns all I/O, receiving at most 32 chunks of 16 KiB. At most 16 workers may remain alive (including stopping workers); session close drops the sender and retains final status. At most 64 entries are retained; closed terminal entries may be evicted when starting another capture. Producers use try_send; overflow drops the sender and reports stopping, worker drains accepted data then reports overflow. Stop identifies both session and capture ID. Worker statuses never contain paths/output. UTF-8 decoder retains at most three incomplete bytes across chunks and fails explicitly on invalid/truncated data. Hard cap is 100 MiB.

UI is a compact token-based terminal status row with shared ConfirmDialog and native save picker; no new prototype (user authorized direct project development). ui-ux-pro-max was unavailable in earlier workspace skill search; preserve shared components and theme tokens. Async path choice pins session identity and mounted generation. Remount re-queries backend status instead of stopping a live session. Poll only active logging, bounded to one outstanding request; errors offer explicit retry. No user data persistence. Kernel filesystem stalls cannot be cancelled; global cap still counts these workers. Stop reports stopping until file flush completes.
