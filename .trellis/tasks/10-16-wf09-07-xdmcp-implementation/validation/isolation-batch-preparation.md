## 本轮工具

在新的本机忽略目录 `.trellis/.runtime/xdmcp-isolation-2/` 中复用已验证的防火墙、独立对照和原始句柄观察工具。没有复制旧恢复 state、停止信号或 session 清理身份。两种 PowerShell 的真实只读 Check 均通过；实际 Apply/Restore 仍由维护者执行。

新增本机 `run-batch.ps1`：

- 检查精确验证程序 hash、无旧进程及全新证据目录；只启动独立 profile 的验证程序，最多等待人工 Apply 一小时，不改防火墙。
- Apply 后再次核对两 store、完整过滤器、动态 NAT 和引擎身份；拒绝已恢复或不新鲜的窗口，之后才依序启动远端观察、专用服务、独立 display102、Windows 原始句柄观察。
- 两个受管实例仍由真实界面的单次许可和连接按钮创建；不通过脚本伪造 UI 或代勾许可，不自动登录。两个 NexaTerm 会话加一个独立对照，共三个桌面。
- 记录服务 InvocationID 和原始进程句柄；三个远端 active session 只记为进程/session 证据，不能代替实际输入验证。
- 应用和独立对照退出后停止本轮专用服务，远端观察继续两分钟并保留活跃/僵尸/session 快照，随后显式结束观察。残留不自动杀除，不借 WSL 后续关机宣称自然回收。
- 服务/观察器提前结束、网络窗口结束或未按期关闭均保留失败；不会自动关闭应用制造“人工正常退出”证据，不自动恢复防火墙。最后的 Restore 仍有活跃引擎保护。

Windows 原生 UI 自动化在本轮再次尝试，仍返回 `native pipe unavailable`；无法代填两个待连接表单，明确交给维护者在 Apply 前完成，不伪报已自动准备。

## 观察器修复与测试

新远端观察器保留上轮已修正的 `loginctl` 重复 `-p` / `--all`。将进程身份观察提取为可独立测试的 tracker：保留退出身份、不重新打开同一已退出 pidfd；`/proc` 里的僵尸持续出现在快照中，区分此前有无活跃捕获，单次记录僵尸状态而不是反复写 gone。PID 复用必须使用新的 startTicks 身份。

实际 Linux 子进程测试用 `waitid(WNOWAIT)` 保留僵尸，覆盖活跃→pidfd退出→僵尸→reap、首次就遇到僵尸、重复采样无事件风暴、PID复用和原有元数据漂移/解析反例。共14项：13通过；真正已登录session用例因当前无登录而显式跳过，不能把它计作本窗口已验证。

PowerShell 5.1/7 均通过：原有18组防火墙模拟、私有ACL/随机认证格式/原始进程隔离工具、缺Apply拒绝与全部脚本解析，以及新批次工具的5组测试。新工具初测真实复现共享日志读取冲突；改用允许既有writer的共享读句柄和小缓冲输出流后，断言真实helper仍存活时就能读到ready输出，而不是等退出才刷出。初始失败日志保留。部分JSON末行暂不消费，完整非法行必须报错。

## 一轮人工验收

1. 验证程序内预填两个 **XDMCP（开发）** 表单，但不连接；管理员运行本轮 Apply 后，不按 Enter、不关闭窗口。
2. 独立 `:102` 登录窗口出现后，连接两个 NexaTerm 实例，人工完成三个桌面登录并分别确认输入和退格。
3. 取消一个受管实例，确认另外两个仍接受输入；重新确认许可并重连该实例，再确认三个桌面可输入。交换两个受管实例，重复关闭/重连隔离验证。
4. 保持两个受管桌面活跃，正常退出 NexaTerm；独立 `:102` 必须仍能输入，随后在它内部 Log Out。
5. 所有桌面/引擎关闭后，在管理员窗口按 Enter 恢复；完成后一次性反馈各项是否成功及最终 RESTORED。代理再核对原始收据和两 store，不依据含糊的“都进去了”单独判 PASS。

目标20分钟内做完；不延长原有30分钟网络窗口。任何提前退出或失败保留现场，不把重试后的成功覆盖到原失败记录。正式随包、完整桌面用例和发行许可仍按原任务缺项继续。
