# 远端会话回收补充核对

日期：2026-11-01。范围：只读复核上一轮持久化 journal 和当前 logind 属性；未启动新桌面、修改防火墙/PAM/logind 配置或杀进程。

## 已确认的结论

**上一轮远端辅助进程最终消失，是发行版关机回收的结果，不是已经证明的单次会话清理成功。** 本地 Windows 引擎先退出、应用exit0、监听/私有目录回收的结论不变；远端回收必须单独验证。

原始现场中，最后一轮应用关闭后及停止专用 XDM 服务后仍有测试 UID 的辅助进程。此次读取同一时间段的 systemd PID1 journal，将相关会话作用域与发行版关机事件关联；只保存选定生命周期消息，不采集认证正文或命令行。

## 尚不能归因的部分

本机当前logind公开属性为 `KillUserProcesses=false`、`UserStopDelayUSec=10000000`。systemd v255文档说明，保留退出后进程的策略与user manager的退出延迟是不同设置。手动注销一轮确有约10秒的user manager退出证据；后两轮作用域则一直保留到关机，不能用普通10秒延迟解释所有残留。

现有记录没有保存残留时每个辅助进程的cgroup、登录session归属和完整PAM关闭边界。因此，**已确认的是最终清理发生在关机时，不是已证明每个残留都由某一项策略或XFCE缺陷造成**。下一次需将同一测试UID下的每个桌面session区分开，不能以UID整体存活判断某个实例失败，也不能终止整个UID来掩盖单会话归属问题。不更改全局KillUserProcesses、不禁用认证代理/PAM来让验收变绿。

依据：[systemd v255用户记录中的killProcesses与stopDelayUSec](https://github.com/systemd/systemd/blob/v255/docs/USER_RECORD.md)、[journal JSON字段契约](https://github.com/systemd/systemd/blob/v255/docs/JOURNAL_EXPORT_FORMATS.md)及本机持久化journal/公开D-Bus属性。journal的MESSAGE可能是字符串、字节数组或多值数组；提取器必须明确处理类型，不能把解析失败当没有日志。此次相关PID1生命周期消息均为文本。
