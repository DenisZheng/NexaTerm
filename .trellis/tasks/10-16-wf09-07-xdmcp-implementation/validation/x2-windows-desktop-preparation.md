## 3. 网络与认证检查

1. XWin 向 TARGET-XDMCP 的 **UDP 177** 发送 direct Query，需允许响应返回本次发送端点；不要把它误记为 Windows 必须监听 UDP 177。
2. 远端桌面的 X 客户端需反向访问 HOST-WIN 的 X TCP 端口。当前 runner 选择 display 100–131，并预检 `6000 + display`，即 TCP 6100–6131；现场只核对实际分配的 display/端口及授权范围，不自动放行整段。
3. `-from` 选择 query 的本地地址，**不证明 X server 仅监听这块网卡**。需另观察实际监听地址与访问策略。TCP 连接测试不能代替 UDP 协商或真实桌面证据。
4. 保持认证与访问控制。不得加 `-ac`、`xhost +`、任意额外引擎参数或自动修改防火墙；普通 SSH TCP 转发和既有 SSH X11 转发也不替代 XDMCP 成功证据。
5. 只用无业务数据的专用账号。Xauthority 的随机 cookie、口令、会话环境和原始报文不进入截图、仓库或 CI artifact。需要抓包时另行明确授权、采集范围和敏感数据处理；本准备工作不抓包。

依据：官方 [XDMCP 协议](https://xorg.freedesktop.org/archive/current/doc/libXdmcp/xdmcp.txt) 的 UDP 端口定义、[Xserver 手册](https://xorg.freedesktop.org/archive/current/doc/man/man1/Xserver.1.xhtml) 的 `-query`/`-from` 语义；具体 display 分配和固定参数以 `src-tauri/src/xdmcp/mod.rs`、`src-tauri/src/xdmcp/platform.rs` 为准。官方 current 手册解释协议语义，不替代所选 21.1.25 引擎的现场验证。

## 4. 当前入口和观察能力的限制

代码基准为 `f46a5fb1c14b35d80d55fb4aa68a6516f764344c`，本次没有改动该实现。

- 后端已注册 `xdmcp_capabilities`、`xdmcp_reserve`、`xdmcp_start`、`xdmcp_stop`、`xdmcp_status`，仅允许主 WebView 调用。没有可直接替代这些命令的项目级 XDMCP CLI；本记录不提供绕过归属校验的启动脚本。
- 请求包含 `executable`、`target`、`local_address`、`allow_external`、`allow_network`；当前地址只接受数值 IPv4，两个许可标记必须显式为真。读取能力或状态不能启动引擎。
- 当前状态只有 `reserved / starting / querying / stopping / closed / failed`。`querying` 仅证明进程已创建且提交了 query 参数，不能标为 `display_ready`、`awaiting_login` 或 `active`。未来阶段需要独立可验证的引擎证据。
- 15 秒是当前 start 等待预算，不是等待用户在远端登录的截止；2 秒 stop 等待后可以返回 `xdmcp_stop_pending`，此时资源仍归属 worker，不能当已关闭。
- 当前 stdout/stderr 不保留，Windows 参数另指定 `-logfile NUL`。仅靠现有状态不能区分认证拒绝、远端拒绝和网络丢包。真实界面/受控远端观察可记录事实；若要增加诊断，须另按敏感信息边界设计，不能从 `start_failed` 猜出具体原因。
- `bundled=false`、`desktop_verified=false` 继续成立。原生 fixture 验证进程归属，不验证引擎认证协商、图形桌面、日志/OS socket 或安装包。

## 5. 执行顺序与可判定结果

所有用例当前均为 **NOT-RUN**。开跑时每行记录实际构建 SHA、环境角色、起止时间、观察证据及 PASS/FAIL/BLOCKED；BLOCKED 必须写具体缺口，不能算 PASS。

| 用例 / 验收编号 | 操作与前置条件 | 必须观察到的结果与证据 |
| --- | --- | --- |
| W01 / X01 | 在干净标准用户环境安装获准的候选包，不预装 X server | 包内引擎、DLL、XKB 数据、notice/源码安排、架构/hash/签名与批准清单一致；无系统 PATH 偶然依赖。仅 external 可用则此项 BLOCKED |
| W02 / X02、C02 | 先查看能力/状态；拒绝本次外部引擎或网络许可，再显式同意后启动 | 未同意时不创建进程/监听；后端拒绝绕过 UI 的请求。开始后阶段如实显示，不能由端口或 PID 推断登录 |
| W03 / X02 | direct-query 到授权靶机，等待登录界面，人工登录专用账号 | 实际登录界面、桌面显示和输入均有证据；只到 `querying` 或仅有登录框不算完整桌面成功 |
| W04 / X02 | 在专用账号的允许尝试范围内输入错误口令，再取消 | 拒绝事实可观察；不泄漏口令，不伪报 active；取消后所属进程、认证目录和监听回收。不得触发生产账号锁定 |
| W05 / X02 | 使用预先安排的拒绝目标、无服务目标和可控不可达目标，分别测试 | 三种情况独立记录；状态不能假成功，取消可靠。无法分类时如实记录观察能力缺口，不以增加重试或放开认证“修复” |
| W06 / X02、X03 | 分别在 reserve 后、启动中、登录框和已登录桌面取消/关闭 | 仅回收该运行；晚到启动不能脱离所有权。`stop_pending` 期间保留归属，最终用实际进程/目录/监听消失确认，不只看 UI 删标签 |
| W07 / X03 | 两个实例分配独立 display；关闭其中一个，再重连；保留外部引擎对照 | 另一实例和外部引擎继续工作；新运行使用新句柄/认证状态，旧 ID 不能停止替代运行；不按全局进程名清理 |
| W08 / X03 | 远端 logout、引擎自然退出/失败、正常退出 NexaTerm，分别测试 | 每次独立验证进程树、运行目录和端口。应用正常退出必须等待真实清理；仅 leader 退出或 registry 为空不足以通过 |
| W09 / X03 | 在专用测试环境另行批准后强制结束宿主 | Windows Job 回收须以原始进程身份观察；不杀其它 NexaTerm 会话。不把此结果外推到尚未实现硬崩溃监督的 Unix |
| W10 / X04 | 分别检查必要扩展、调整分辨率/缩放、US/DE 键盘及中文输入 | 记录候选引擎真实能力/限制，键位与显示正确；XKB 编译往返成功不能代替现场键盘/输入法验收 |
| W11 / X04 | 剪贴板策略确认后，用无敏感信息样本测试其允许/禁止方向 | 行为符合已确认策略；未确认则此子项 BLOCKED，不默认开启双向同步 |
| W12 / X04 | 已批准的多网卡/NAT拓扑逐项重复 direct-query 与反向连接 | 核对实际源地址、监听和目标范围；不得通过全接口放开策略掩盖失败。直连通过不外推其它拓扑 |
| W13 / C01、C02 | 在实际 UI 中测试三主题、保存/导入/重启与既有协议回归 | 入口符合已确认原型；状态/能力文案准确；不持久化 cookie、运行句柄或瞬态许可，不凭快照重启外部引擎。现有无 UI 基线不能通过此项 |
| W14 / X01、X04 | 在专用测试账号分别有/无 `.XWinrc` 的环境检查配置优先级、私有路径和菜单；只用无副作用的可辨识测试配置，不执行菜单命令 | 核对 HOME 配置优先于 system 配置的实际行为，避免用户配置污染验收；stock 菜单中的 xterm/emacs/xload 不因此成为发行依赖。配置选择或缺配置行为无法观察时记录缺口，不套用仅属 Cygwin 的 fallback |

清理观察复用 `src-tauri/test-fixtures/xdmcp_observed_process.rs` 与 `src-tauri/src/xdmcp/tests.rs` 的身份原则：先捕获所属进程身份，后验证同一对象停止，避免 PID 回收复用造成误判。实际桌面观察需要适配现场入口；这不是已交付的自动化验收工具。

W14 的固定源码依据及样例菜单/图标注释的区别见 [资源权限与配置分发边界](../research/windows-resource-rights-review.md)。当前样例的身份验证不等于批准原样作为产品配置；如选择独立最小配置，必须先评审并同步固定来源及资源核验，不能在验收时临时替换使测试通过。

## 6. 记录与停止条件

原始受控材料可放 `.trellis/.runtime/xdmcp-x2/<run-id>/`，不提交；仓库只保存去标识结论、非敏感版本/hash、用例结果和必要截图说明。不要输出完整引擎命令行、Xauthority 内容或认证目录列表。

遇到安全软件再次隔离、组件身份/hash 漂移、未知监听、非所属进程被回收或凭据泄漏时，立即停止相关用例并保留最小必要现场。不能以重试、跳过检查、修改安全策略或手工删除所有 X server 文件使结果变绿。

交付时分别填写：实现状态、自动化、原生集成、真实互通、许可/分发。待办消失、进程 fixture 通过、原生构建通过、真实桌面可用和获准分发是不同结论，不互相替代。
