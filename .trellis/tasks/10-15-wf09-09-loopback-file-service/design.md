# Design
One app-managed FileServiceManager owns one UUID reservation, 15s unused expiry, one file-read worker permit and a 64-entry transient audit ring. reserve/start/stop/status/audit commands require main webview. Start consumes once, holds a RAII lease, reads only a selected regular file with limit+1 into an immutable bounded buffer, then binds numeric127.0.0.1. OS blocking file reads retain their permit after cancellation/timeout until actual completion; five-second startup deadline bounds waiting. Explicit privileged ports rejected; zero requests OS assignment. Reuse getrandom-backed MCP token generator without persisting its value.
HTTP module accepts only GET/HEAD /file over HTTP/1.1, exact Host and one Bearer header, no Origin, query, body or transfer encoding; limits8KiB headers, four active clients, five seconds per request. Always close; no CORS; attachment/octet-stream/nosniff/no-store. No filenames or paths in requests/responses. Backend server has15-minute lifetime; stop acknowledges only after listener and request tasks are dropped. Window/exit cleanup signals and waits; inactive/late UI operations cannot orphan a newly started service. Main-window status permits recovery of an already-running service without returning its token; an adopted instance is stopped only on explicit action, not by an unrelated panel unmount.
UI is extracted/lazy under existing Tools, uses existing form/buttons/token styles, AppSelect where needed, native single-file picker and explicit clipboard action. Show transient bounded audit events (not a durable compliance trail); manual refresh, no automatic request payload logs. Status reads while visible/running detect expiry. No settings/schema/dependencies/capability permissions change. ui-ux-pro-max unavailable as previously recorded; repository shared UI is the design baseline.
