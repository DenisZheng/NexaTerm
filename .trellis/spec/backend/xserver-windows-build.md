# Windows X server build evidence (X0)

## 1. Scope

The GDI-only Windows development recipe builds the fixed upstream server and direct/transitive X libraries in a private prefix. It does not install into NexaTerm, enable bundled capability or approve a component license. No external implementation is committed. Build logs and JSON evidence distinguish compilation from native startup, dependency/license closure and desktop interoperability.

## 2. Entry points

`python scripts/xserver_windows_build.py --work <private-directory> --report <json>` runs under MSYS2 UCRT64 on a real Windows runner. `scripts/xserver/windows-sources.json` owns fixed source URLs, byte sizes, SHA256, root paths, license anchors and configure options. The server retains #84's source/signature/key verification; dependencies are fixed official HTTPS inputs, with their signature/provenance status recorded separately.

`xserver_windows_pe.parse_pe(bytes)` validates AMD64/PE32+ headers, bounded sections/RVAs and both normal/delay import descriptors, returning their union. `xserver_windows_inventory` binds installed files to their source owner, records actual DLL provider package/license hashes and checks the server's GNU link map for static/compiler-runtime inputs. The Autotools target is `XWin.exe`; the Meson target name is not substituted into this recipe.

`python scripts/xserver_windows_signatures.py --cache <directory> --report <json> [--offline]` independently verifies all dependency archive/signature/certificate pins, including the actual signing subkey and primary fingerprints. It shares the fixed download path with the native recipe. The source workflow executes this on Linux as well as the native recipe checking each dependency before extraction/build.

`xserver_windows_licenses.source_license_evidence` verifies a specifically reviewed missing-installed-notice package against `toolchain-license-sources.json`. This fixed source receipt is separate from installed license files and never approves distribution.

## 3. Contracts

- Verify complete archive hash/size before reading or extracting. Extract only canonical regular files/directories below the pinned root; reject traversal, duplicates, links and special files, with bounded entry count and total bytes. Do not preserve ownership or privileged mode bits.
- Preserve verified release file timestamps so Make does not regenerate shipped Autotools inputs. Resolve the host `xcbgen` module from its exact private installation and verify its imported file; target pkg-config Windows path rewriting does not change the build-only Python module's owner.
- Pinned source adaptations require exact input/output file hashes and the exact authored occurrence count (default one) for each replacement. A mismatch fails before writing the adapted file. The libxcb Winsock buffer casts retain the original integer payload/length. LibX11 scalar varargs use explicit intptr_t/uintptr_t bridges while preserving public scalar widths and sign extension; compiler diagnostics are not disabled. Font buffer CRT descriptors use a signed intptr_t bridge to/from the existing opaque private field; preserve IO/close behavior and exercise actual target archive binary write/flush/read/EOF before building the server.
- Verify each dependency signature with an isolated pinned public certificate and zero GPG exit. Match both full signing and primary fingerprints, epoch and algorithms. Reject revoked/expired current signing or primary keys, unknown/error statuses and duplicate signatures. An old `KEYEXPIRED` note is accepted only when its timestamp belongs to another explicitly present certificate key; it cannot excuse the current signer. Legacy primary algorithms/digests and maintainer identity remain adoption review items.
- GnuPG 2.2 may emit `VERIFICATION_COMPLIANCE_MODE`: accept only its documented nonempty unique flags 8/23 as reported metadata. It never substitutes for GOODSIG/VALIDSIG or changes distribution approval. Unknown flags/statuses still fail; failure reports retain only bounded status names and the current component.
- The Windows Xwinsock wrapper includes ws2tcpip.h before restoring namespace aliases. Immediately after installing xorgproto, compile and execute a real numeric IPv6 loopback conversion/resolution probe with balanced WSA startup/cleanup; it opens no connection. GNU make -k collects independent compilation failures, but its nonzero exit still fails the build before installation.
- Keep client and server geometry header contexts separate. Disable xorgproto legacy public installation and verify libX11 owns the pinned client XKBgeom.h. This server release uses its own xkb/xkbgeom.h and include/xkbstr.h; pin both files and require their actual dependencies in both xkb.c and xkbUtils.c. A client or unused legacy copy cannot satisfy this observation. Do not add an unused protocol header directory or waive install collisions: retain both hashes/owners in failure evidence.
- Use a private source/build/prefix tree; no system installation, elevation, arbitrary CLI URLs or unreviewed downstream source. Command arguments come from the tracked recipe, with a fixed Windows target and explicit 2D/XDMCP options. Build tools and target libraries are separate inventories.
- Native server build must produce AMD64 PE, actual XDMCP configuration, and a real native version probe. Inspect direct/transitive PE imports against explicit prefix/toolchain providers; Cygwin/MSYS runtime imports are failures. Do not infer the closure from configure lists or a process existing.
- DLL checks include delayed imports, unknown/malformed RVA/descriptor failures and provider ambiguity. System DLL names cannot be shadowed by a file in the private prefix. Prefix file collisions and unattributed source binaries fail. The final link map must identify XWin.exe; actual loaded link inputs retain hashes and package/source ownership rather than inferring static runtime use from compiler defaults.
- GNU ld 2.47-4 also reports in-memory BFD inputs, not disk files: XWin_exe_rtr/ertr objects and dll stuff. Capture the actual GCC-selected linker binary/hash/package/license as a build tool, and require an early real DLL data-import/run probe before heavy dependencies. Bind every recognized memory input to its allowed non-discarded map sections and actual final PE contribution bytes/offsets/hash; check pseudo-relocation headers/table and the real relocator reference. Preserve inputFilePresent=false and unavailable input-file hashes. Unknown missing files, wrong producers, disk shadows, missing/overlapping/out-of-image sections or modified relocation data still fail. Producer license metadata is not output adoption approval; no linker implementation is copied.
- Every source component has pinned license text hashes. A collected license file is evidence, not a blanket MIT label for all source files. Record generated parser exceptions, compiled inputs, installed resources and any unresolved per-file/compiler-runtime obligations before distribution approval.
- Missing installed package notices still fail unless a reviewed source receipt matches the exact package/version/declaration, complete installed file set and every object byte pin, plus the pinned source repository notice. The default-manifest receipt retains the publisher's Public Domain declaration separately from the BSD source notice and the archive/build/source identities. Keep `licenseFiles` empty and `installedLicenseTextPresent=false`; do not synthesize installed text, copy the generator implementation or infer adoption. Unknown versions/files/declarations/bytes/notices fail. Preserve completed static-map inputs/packages and the bounded current input when a later record fails.
- Preserve server Automake dependency tracking. Verify actual winmsg and GDI compilation, absence of the message header without a license notice, and absence of both local/SDK DirectDraw headers and backend. The fixed GDI selector retains the real GDI callbacks, rejects unsupported requested engines and propagates initialization failure. Remove the DirectDraw loader, private fields, backend object and dxguid archive; the SDK DirectDraw header is LGPL, not an approved permissive substitute. Missing observations or a DirectDraw link input fail, even if configuration claims the expected profile. These checks cover the named server questions; they do not assert an exhaustive per-file review of every transitive library.
- Exclude the LGPL SDK propkey.h property table. Share the existing permissive single AppUserModel key declaration across compiler branches, retain the real IPropertyStore interface, and run a native function-table/key/value probe in the actual Xproto/Xwindows include order. When the protected SDK interface was parsed before INITGUID, re-include its unguarded Public Domain propkeydef.h afterwards to refresh DEFINE_PROPERTYKEY; initguid.h alone only refreshes DEFINE_GUID. Require observed AppID compilation and absence of propkey.h from all server dependencies. Pin the Bison interface header and embedded/installed resource identities separately; an XML/icon/config without an independent permission notice remains unresolved.
- Enable dependency tracking for target libraries as well as the server. Enumerate actual GCC Automake dependency records and valid Ninja dependency nodes, retaining record hashes and per-file bytes/hash/source or package ownership and consumer components. Handle escaped native paths/whitespace and nonrecursive Makefile working directories; missing/unknown roots, stale/incomplete Ninja records or unowned installed/generated files fail. Known bootstrap dependency comments do not count as compiler observations. Cache exact pacman file inventories per package and reject conflicting file ownership. Preserve bounded current raw/resolved input paths on failure and the completed DLL package evidence before later gates. This is observed C build evidence (including target utilities built only for development), not proof that each input ships or that all file licenses/resources have been approved.
- Preserve LLP64 semantics: address masks/alignment use uintptr_t, signed opaque scalar tokens use intptr_t, and public XID widths remain unchanged; pointer diagnostics use %p. Load Windows/COM and Winsock declarations inside consistent SDK aliases before restoring X11 types. The XCB-first order must retain separate native BOOL/INT32/64 and protocol types. Explicit missing-file creation must pin an authored declaration overlay, require absence and never overwrite input. Keep the select fallback structure separate from SDK WSAPoll and exercise a real loopback socket through the actual os archive. Upstream Unix fork/wait test executables are explicitly outside the native profile, not counted as passed; application CI and native evidence/probes remain required.
- Report schema 1 preserves `distributionApproved=false`, `bundled=false`, `desktopVerified=false`. A failed build writes fresh FAIL with the component/stage and nonzero exit, retaining prior completed evidence; no success fallback or continue-on-error. Native build success alone cannot pass the release gate.
- CI has contents-read permissions and no persisted checkout credentials. Only explicit JSON evidence is uploaded; no upstream archive/source or unapproved engine binary is published in this slice.

## 4. Error matrix

| Condition | Result |
| --- | --- |
| Fixed source plus native build/probe/import checks pass | Development evidence, adoption remains pending |
| Missing tool/network/hash/license anchor | FAIL, nonzero |
| Unsafe archive or unexpected component content | FAIL before execution |
| Configure/compile/install/probe fails or times out | FAIL with exact component/stage |
| Missing/wrong-architecture PE, unresolved/ambiguous DLL or POSIX runtime import | FAIL |
| Native desktop/login or signed installer absent | Explicit false capability; never inferred |

## 5. Good / base / bad

Good: the pinned upstream MinGW path produces native PE, with actual imported DLL providers and source/license evidence. Base: rebuilding the same inputs records the same source/license identities without promising bit-identical output from a changing toolchain. Bad: using host Cygwin libraries, adopting an aggregate fork by its top-level label, suppressing a configure failure, or marking bundled after a version probe.

## 6. Tests

Exercise corrupted inputs, unsafe archive paths/types/budgets, changed license anchors, failed/timeout build tools, malformed PE/import data and POSIX/unresolved dependency rejection. Real Windows CI must execute the native recipe; mocks or Linux compilation cannot substitute for its PE/probe evidence. Keep application CI, security and license checks unchanged.

## 7. Wrong / correct

Wrong: copy the entire toolchain bin directory beside the server, call every DLL MIT, or treat the configured link graph as observed runtime dependencies.

Correct: inspect actual PE imports recursively, map each shipped candidate to its exact provider/hash/license, leave unresolved obligations explicit, and adopt only after that review and later installer/desktop verification.
