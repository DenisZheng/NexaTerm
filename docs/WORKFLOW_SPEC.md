# NexaTerm 工作流规范（WORKFLOW_SPEC）

> 版本：0.2（2026-09-23，WF-01 开工前维护者确认 D1–D8；0.1 于同日由 WF-00A 建立）
> 依据：维护者 2026-09-23 的方向授权、`NEXATERM_WORKFLOW_DELIVERY_PLAN.md`（交付方案）与 `NEXATERM_REQUIREMENTS.md`（原需求）。
> 定位：**当前产品交互规则的唯一正文**。AGENTS.md、`.trellis/spec/` 索引、任务 PRD 只按规则编号引用本文，不复制正文；工程规范（token、Radix、lazy loading、凭据、Host Key、许可证、测试）仍在各自 spec 中维护，本文不覆盖它们。

## 0. 阅读方式

每条规则带四个字段：

| 字段 | 含义 |
| --- | --- |
| 编号 | `WS-<域><序号>`，被 AGENTS、spec index、任务 PRD、检查脚本说明引用 |
| 状态 | **已确认**：维护者已授权的方向，实现与检查都以此为准。**默认值**：交付方案 §3 给出的建议默认值，未被推翻即按此实现；原型评审推翻后回写本文并升版。**待确认**：方案自身标注需原型/测试，或与原需求存在差异，实现前必须先对齐 |
| 阶段 | 首次落地的交付包（WF-xx）；落地前，该规则只约束设计与验收表述，不要求当前代码已满足 |
| 正文 | 规则本身 |

同一条规则的"当前实现"事实写在 `docs/CURRENT_STATE.md`，不写在本文；本文描述目标。旧规则的替代关系见 §11。

## 1. 会话模型（WS-M）

| 编号 | 状态 | 阶段 | 规则 |
| --- | --- | --- | --- |
| WS-M01 | 已确认 | WF-01 | 三个概念分别建模：**保存配置**（profile，长期存在，可打开多个实例）、**工作区会话实例**（每个打开的会话有独立逻辑 ID、目录、标签状态、关闭行为和 MultiExec 选择）、**底层运行时句柄**（Rust terminal sessionId、RDP/VNC runner id，可因重连变化，不作为身份，不写入恢复快照）。 |
| WS-M02 | 已确认 | WF-01 | **顶层标签代表实例，不代表配置。** 同一保存配置可以打开多个实例，每个实例是可直接选择、可关闭的工作区项。Local/WSL/RDP/VNC 实例与 SSH 实例共用同一套标签呈现。 |
| WS-M03 | 已确认 | WF-01 | **当前上下文 = 活动工作区项 + 活动 pane。** 工具栏可用性、Files 绑定、状态栏、快捷键作用对象全部从当前上下文派生，不再各自维护"当前连接"。 |
| WS-M04 | 默认值 | WF-01 | 分屏后可以显示一个包含多个 pane 的工作区项；pane 内仍保留独立实例身份。同一实例切换展示位置时不重复连接；只有明确选择"新建会话"才新建底层连接。 |
| WS-M05 | 已确认 | WF-01 | 实例视图先用 selector 从现有 Terminal/Local/RDP/VNC 集合投影，不复制第二份会话数据。标签顺序可有独立的 ID 顺序表，其职责仅是排序。若最终需要统一实体集合，在接入阶段逐项迁移并删除旧 owner。 |
| WS-M06 | 已确认 | WF-00B | 保留现有 home/settings 与记忆指针的行为测试。旧指针与 `homeActive` 不得未经验证就宣称为可删除的派生值。 |

## 2. 主窗口与入口（WS-E）

| 编号 | 状态 | 阶段 | 规则 |
| --- | --- | --- | --- |
| WS-E01 | 已确认 | WF-01 | 主窗口提供**统一入口**：菜单 + 高频工具栏 + 上下文菜单 + 快捷键调用同一动作入口，能力判断集中派生。工具栏中尚未实现的功能显示可用状态及原因，不能点击后静默无响应。 |
| WS-E02 | 已确认（v0.2） | WF-01 | 菜单分组：**会话、视图、终端、工具、设置、帮助**，不设 File 菜单；导入/导出归"会话"，偏好归"设置"，退出归"会话"末项。原需求 §34 的 File 菜单条目按此重新归属。 |
| WS-E03 | 默认值 | WF-01 | 高频工具栏包含：新建会话、分屏、MultiExec、隧道，以及 capability 可用时的 X11；支持图标+文字 / 紧凑 / 仅图标（需求 §35）。 |
| WS-E04 | 已确认 | WF-01 | **左侧为 Sessions / Files 切换。** SSH 实例连接成功后默认显示该实例的 Files，可切回 Sessions；切换不得重建 SSH 连接。 |
| WS-E05 | 默认值 | WF-01 | 中间以终端和远程桌面为主；远程编辑器继续提供现有能力，在所属 SSH 工作区内部显示。 |
| WS-E06 | 已确认（v0.2） | WF-01 / WF-03 | Monitor、Docker、命令库、AI、隧道等**保留在右侧可收起工具面板**，Files 移到左侧后右侧只承载这些次级工具；保持按需加载。WF-01 不改这些工具的内部布局（WF-04 前冻结新功能）；窄窗口下右侧面板默认收起。 |
| WS-E07 | 已确认 | WF-01 | 首页保留最近、收藏和快速连接（需求 §29）。本轮先完成入口与行为，不单独排配色美化。 |
| WS-E08 | 已确认（v0.2） | WF-01 | 窄窗口：**工具栏按优先级折叠进 `⋯` 溢出菜单，菜单栏保留**；顶层实例标签沿用现有"固定可见数 + 活动项钉住 + `⋯` 菜单"机制。原型展示三种状态：空工作区、一个 SSH + Files、四 pane + MultiExec 目标面板，外加窄窗口。 |
| WS-E11 | 已确认（v0.2） | WF-01 | 实例标签标题为 `<配置名> · 终端 N`（沿用每连接内 ordinal）；Local/WSL 为 `<profile 名> · N`；RDP/VNC 为 `<配置名> · RDP` / `· VNC`。标签可重命名留待后续。 |
| WS-E12 | 已确认（v0.2） | WF-01 | 分屏组在顶层显示为**一个**标签，标题取宿主实例；pane 内实例不再在顶层单独出现（WS-M04 的具体化）。 |
| WS-E13 | 已确认（v0.2） | WF-01 | Local/WSL 每个终端实例一个顶层标签，与 SSH 并列；现有聚合"本地"入口退役（WS-M02 的具体化）。 |
| WS-E09 | 已确认 | WF-01 | 新入口建立时引入 English/zh-CN 资源与 OS 快捷键标记，不再新增硬编码中文；旧面板全量迁移留到对应包（需求 §41）。实现方式（v0.2 确认）：自建最小 `t(key, params)` + JSON 目录 + `useLocale`，不引入 i18n 依赖；后续需要复数/ICU 再评估。 |
| WS-E10 | 已确认 | WF-01 | 复用 `src/features/shortcuts/`（registry / manager / validation）扩展菜单与工具栏的动作元数据，不另起快捷键注册中心；重型 RDP/VNC、Monaco、文件工具保持按需导入，新增入口不得把它们带入初始 chunk。 |

## 3. 新建、编辑与快速连接（WS-C）

| 编号 | 状态 | 阶段 | 规则 |
| --- | --- | --- | --- |
| WS-C01 | 已确认 | WF-02A | 新建会话主操作为**"保存并连接"**；可选"仅保存"；测试连接是辅助操作。"保存并连接"只创建一次会话，提交中不可重入。 |
| WS-C02 | 已确认 | WF-02A | 编辑现有配置默认只保存，不终止或重连正在运行的实例；"保存并新建连接"是显式动作。 |
| WS-C03 | 已确认 | WF-02B | 快速连接支持 `user@host`、`ssh://user@host:port`，使用结构化解析，不把输入交给 shell 拼接。缺少用户/认证时沿用现有认证 UI。 |
| WS-C04 | 已确认 | WF-02B | 快速连接默认是**临时会话**；成功后可"保存为会话"；失败或取消不得留下伪装成正式配置的数据库记录，也不得靠自动插入伪保存记录让文件 API 工作。 |
| WS-C05 | 已确认 | WF-02B | 默认不从 URL 接收密码。IPv6、端口范围、空白与非法输入有明确规则和测试。 |
| WS-C06 | 已确认 | WF-02B | 临时会话的认证材料与 SFTP 上下文由 Rust 内存上下文持有，前端只持不透明引用；不得把完整密码复制到 workspace state 或 localStorage。临时上下文需定义所属实例、认证材料生命周期、重连是否重新询问、关闭后何时释放、活动传输/编辑如何收尾。 |
| WS-C07 | 已确认 | WF-02 | 继续复用现有密码/密钥/PPK/凭据与 Host Key 流程；Host Key 首次确认、变化拒绝、密码错误、密钥口令、用户取消都有独立结果；失败不污染最近成功记录。 |

## 4. 文件与终端联动（WS-F）

| 编号 | 状态 | 阶段 | 规则 |
| --- | --- | --- | --- |
| WS-F01 | 已确认 | WF-03 | **Files 绑定活动 pane 对应的 SSH 上下文。** 同一主机的两个终端可以分别处于不同目录；切换焦点后 Files 跟随。 |
| WS-F02 | 已确认 | WF-03 | 提供明确的**"跟随终端目录"开关**，状态按实例保存。跟随开启且检测到目录事件时自动定位；手动浏览到其它目录时清楚显示当前跟随状态，不得暗中反复抢回目录。 |
| WS-F03 | 待确认 | WF-03 | 跟随开关的默认值，以及"手动浏览后自动暂停跟随并给恢复按钮"是否采用。方案建议采用；原型确认。 |
| WS-F04 | 已确认 | WF-03 | 沿用已有 OSC7 / 简单 `cd` 识别与手动定位；检测不到目录时保留手动操作，不伪造识别成功；不向交互终端写入探测命令，不解析任意命令输出。 |
| WS-F05 | 已确认 | WF-03 | 缓存、请求序号、取消/过期响应保护以实例或 pane 上下文区分：标签切换期间 A 的慢响应不能覆盖 B 的列表。复用现有 tab 级 stateKey 与目录请求失效保护。 |
| WS-F06 | 已确认 | WF-03 | Files 视图从现有 `RemoteFilePanel` 的 files/monitor/AI/commands/tools 混合容器中抽出可复用的文件视图；只把 Files 视图接到左侧，其它工具保留次级入口（位置见 WS-E06）。 |
| WS-F07 | 已确认 | WF-03 | 非 SSH 实例激活时，Files 显示该协议实际可用的文件能力或说明，不残留上一台主机的可操作列表。已保存 SSH 与临时 SSH 行为一致。 |
| WS-F08 | 已确认 | WF-03 | 上传下载保持现有队列和重试；继续使用 Monaco 与远端 mtime/size 冲突检测；未保存编辑的关闭确认不能在布局调整中丢失。 |
| WS-F09 | 待确认 | WF-03 | 关闭实例时仍在运行的传输如何处理（询问 / 继续托管）。任一策略都必须防止视图关闭后操作无人管理。 |

## 5. 分屏与 MultiExec（WS-X）

| 编号 | 状态 | 阶段 | 规则 |
| --- | --- | --- | --- |
| WS-X01 | 已确认 | 现有 / WF-04B | 首批沿用现有 2/4 pane、横向/纵向、拖动比例；`terminalSplitMaxPanes = 4` 本轮不扩展。 |
| WS-X02 | 已确认 | WF-04B | 清楚区分"把已打开实例放入 pane"和"为 pane 新建实例"；一次命令的焦点目标唯一。 |
| WS-X03 | 已确认 | WF-04C | **MultiExec 统一为 `off / live / send` 三态**，吸收现有 Split Sync Input 与 Command Sender。目标以**会话实例 ID** 标识，可勾选同一连接的两个终端；不再按 connectionId 每组只选一个。 |
| WS-X04 | 待确认 | WF-04C | 目标集合是否在显式选择后固定、切换焦点不暗中更换 send 目标。方案推荐固定；相比当前 active-tab 同步目标是有意的产品变化，需原型和测试后确认。 |
| WS-X05 | 已确认 | WF-04C | 只显示当前能接受终端输入的实例作为目标：SSH/Local，以及验证过输入契约的 Serial/Telnet；RDP/VNC 不伪装成终端广播目标。 |
| WS-X06 | 已确认 | WF-04C | live 输入由一个来源分发，避免同一按键经两个监听重复写入；目标断线后失效，重连不会无提示重新加入广播。 |
| WS-X07 | 已确认 | WF-04C | send 结果区分"已写入终端 / 写入失败 / 目标已断开"；PTY 写入成功不等于远端执行成功；不自动对不确定的批量命令重发。 |
| WS-X08 | 已确认 | WF-04C | 终端快捷键与菜单快捷键统一分发；中文输入法组合态、粘贴、Ctrl+C 由明确的终端输入规则处理（需求 §40）。MultiExec 激活时有显眼状态与停止按钮（需求 §21）。 |
| WS-X09 | 待确认 | WF-04B | 文件夹"连接全部"是否默认递归包含子组、并发上限、预览数量。方案建议默认包含且预览数量。部分认证失败不回滚已成功会话；取消只处理本批尚未完成的连接。 |

## 9. 三个基准问题（WF-00A 验收）

| 问题 | 当前规范答案 |
| --- | --- |
| Files 在哪里？ | 目标：左侧 Sessions / Files 切换（WS-E04），绑定活动 pane 的 SSH 上下文（WS-F01）。当前实现仍在右侧工具面板，这是 `CURRENT_STATE.md` 记录的事实，不是约束。 |
| 标签代表配置还是实例？ | 实例（WS-M02）。当前实现按 connectionId 分组、Local 聚合为一个入口，将在 WF-01 改为实例投影。 |
| MultiExec 选择什么？ | 会话实例（WS-X03）。当前实现每个连接只选一个子 tab，将在 WF-04C 改为实例目标集合。 |

## 10. 待确认事项清单

实现对应阶段前必须先对齐；对齐结论回写本文并升版。v0.2 已确认并移出本清单：WS-E02、WS-E06、WS-E08、WS-E11–E13、WS-E09 实现方式；原型状态切换允许使用少量 JS（母版 AGENTS 条目本要求可点击伪功能）。

1. WS-F03 跟随开关默认值与"手动浏览后暂停跟随"。
2. WS-F09 关闭实例时运行中传输的策略。
3. WS-X04 MultiExec 目标集合固定 vs 跟随焦点。
4. WS-X09 "连接全部"递归/并发/预览。
5. WS-N04 Windows X server 分发方案。
6. WS-R03 未保存编辑内容恢复。
7. 树形分组：`ConnectionPane` 的 localStorage `parentId` 树与 SQLite 平面 `connection_groups`、全局唯一 name 的冲突（WF-04A 前决定允许范围）。
8. 若首批用户主要从 MobaXterm 迁移，是否提前会话导入优先级（方案默认不扩大）。
