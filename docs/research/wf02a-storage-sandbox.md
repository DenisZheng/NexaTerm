## 已确认的根因

本机开发进程继承了启动器的文件操作沙箱。沙箱允许创建和写入临时文件，但拒绝对应用数据目录中的保险库及临时文件执行 `file-write-unlink`。原子替换已有文件需要该权限；失败后的临时文件清理同样需要该权限。

脱敏证据来自本机 `~/.workbuddy/logs/sandbox/20261001/sandbox_47057_000.log`：

| 时间 | 日志行 | 事件 |
| --- | --- | --- |
| 16:46:09 | 26602 | `Sandbox: nexaterm(...) deny(1) file-write-unlink <app-data>/mxterm.db-journal` |
| 17:20:43 | 68408–68409 | 拒绝替换 `secrets.enc`，随后拒绝清理对应临时文件 |
| 17:28:35 | 87131–87132 | 同上，第二个临时文件 |
| 17:28:43 | 87149–87150 | 同上，第三个临时文件 |

三次保险库拒绝事件与交接中的三个残留临时文件逐一对应。检查时目录和文件属主正常，未发现 immutable 标志或显式 ACL。该证据指向进程运行权限，不支持通过改变 Keychain 策略、加密算法或原子写入方式修复。

## 对旧交接结论的修正

- `SQLITE_IOERR_DELETE` 本次有明确的沙箱拒绝证据，不能归因于多个 SQLite 连接争抢删除 journal。`busy_timeout` 处理锁等待；WAL 改变日志机制，不能替代正确的运行权限。
- 临时文件完整只证明加密、序列化和写入取得进展，单凭文件存在不能区分同步、备份复制与最终替换失败。上述系统拒绝日志补齐了关键证据。
- `storage.rs` 诊断于 17:31 加入，`storage_vault.rs` 诊断于 17:35 加入，均晚于上述三次失败。后加诊断的空 stderr 不能排除之前执行了原子写入路径。
- 本轮检查时 NexaTerm / cargo / watcher 已不在运行，不能沿用“等待 watcher 编译即可”的状态。
- macOS 原生 Keychain 常规读写错误经 `vault_local_keychain_unavailable` 返回；本次没有证据支持改用明文密钥文件。迁移修复仅对缺失 secret 且存在匹配历史材料的条目补写，不是无条件重写全部 secret。

## 本轮处理与边界

1. 移除五个 Rust 文件中的临时 `[sqlite-dbg]` / `[vault-dbg]` 打印；保留原有脱敏 `AppError` 日志。
2. 修正 WAL 注释中的错误归因；保留接手前已有的 busy timeout、WAL、版本标记幂等和前端改动，未借此扩大修复。
3. 经系统明确授权启动开发应用，使其能够正常替换自身数据文件；不修改或绕过启动器沙箱规则。
4. 不删除或重建现有保险库，不改 Keychain，不手工把残留临时文件覆盖到主文件。修复与验收期间未提交或推送，后续交付按用户明确授权执行。

已有修改仍有独立评审边界：版本标记的幂等写入未证明首次并发建目录的原子性；`useConnections.remove` 失败时吞掉异常并异步 reload，调用者可能继续执行删除成功后的会话清理。两者不应因本次运行权限修正而自动标记为验收通过。
